## Цель проверки

Проверить, дает ли режимная модель рынка полезный торговый сигнал на дневных свечах. Базовая сделка исполняется по схеме:

1. На закрытии дня `t` доступны данные до `close_t` включительно.
2. После `close_t` рассчитываются режим, матрица переходов и вероятности режима на следующий день.
3. Вход выполняется на `open_{t+1}`.
4. Выход выполняется на `close_{t+1}`.
5. Доходность сделки считается как open-to-close доходность следующего дня с учетом комиссии и проскальзывания.

Такой протокол не использует будущие данные и подходит для честного walk-forward бэктеста.

## Термины

- `MM` - observable Markov Model, то есть наблюдаемая марковская модель режимов.
- `HMM` - Hidden Markov Model, скрытая марковская модель, где режимы выводятся из данных без ручной разметки.
- `Bull`, `Bear`, `Sideways` - три рыночных режима.
- `transition_matrix` - матрица вероятностей переходов между режимами.
- `stationary_distribution` - долгосрочная доля времени, которую модель ожидает в каждом режиме.
- `signal` - направленный торговый сигнал, рассчитанный как `P(Bull next) - P(Bear next)`.

## Входные данные

Минимальный набор дневных свечей:

| Колонка | Обязательна | Описание |
|---|---:|---|
| `date` | да | Дата торгового дня |
| `open` | да | Цена открытия |
| `close` | да | Цена закрытия |
| `high` | нет | Максимум дня, пригодится для расширений |
| `low` | нет | Минимум дня, пригодится для расширений |
| `volume` | нет | Объем, пригодится для расширений |

Данные должны быть отсортированы по возрастанию даты. Дубликаты дат и пропуски `open`/`close` должны отбрасываться или явно обрабатываться до расчета сигналов.

## Базовая модель MM

### 1. Доходность окна

Для каждого дня `t` считаем доходность за последние `L` торговых дней:

```text
rolling_return_t = close_t / close_{t-L} - 1
```

Базовые параметры:

```text
L = 20
bull_threshold = 0.05
bear_threshold = -0.05
```

Примечание: Pine Script из upstream использует лог-доходность `log(close_t / close_{t-L})`. Для первой Python-версии фиксируем простую процентную доходность, как в upstream `scripts/markov_regime.py`; позже можно добавить тест чувствительности simple vs log.

### 2. Разметка режима

```text
if rolling_return_t >= +0.05:
    mm_regime_t = Bull
elif rolling_return_t <= -0.05:
    mm_regime_t = Bear
else:
    mm_regime_t = Sideways
```

Первые `L` строк не имеют режима, потому что для них нет полного lookback-окна.

### 3. Матрица переходов

Для прогноза на день `t+1` матрица строится только по режимам, известным на момент закрытия дня `t`.

Для каждой пары соседних дней внутри обучающей истории считаем переход:

```text
mm_regime_i -> mm_regime_{i+1}
```

Затем нормируем строки:

```text
P_t[from_state, to_state] =
    count_t(from_state -> to_state) / count_t(from_state -> any_state)
```

Каждая строка матрицы должна суммироваться в `1.0`. Строка означает: "если сегодня режим `from_state`, какова вероятность каждого режима завтра".

### 4. Вероятности следующего дня

Пусть текущий режим на закрытии дня `t` равен `s_t`. Тогда:

```text
mm_p_bear_next_t     = P_t[s_t, Bear]
mm_p_sideways_next_t = P_t[s_t, Sideways]
mm_p_bull_next_t     = P_t[s_t, Bull]
```

Это вероятности следующего режима, а не прямые вероятности роста или падения цены. Для торгового решения используем их как режимный прогноз.

### 5. Сигнал

Базовый сигнал:

```text
mm_signal_t = mm_p_bull_next_t - mm_p_bear_next_t
```

Интерпретация:

```text
mm_signal_t > 0  -> перевес в сторону long
mm_signal_t < 0  -> перевес в сторону short
mm_signal_t = 0  -> нейтрально
```

Для первой проверки фиксируем два варианта позиции:

| Вариант | Правило | Зачем нужен |
|---|---|---|
| `sign` | `position = sign(mm_signal_t)` | Простая проверка направления |
| `proportional` | `position = clip(mm_signal_t / signal_scale, -1, 1)` | Проверка идеи из видео: размер зависит от силы сигнала |

Базовый вариант для первого отчета: `sign`. Вариант `proportional` добавляется как отдельный эксперимент, чтобы не смешивать качество направления и качество сайзинга.

## Walk-forward протокол

### Базовый режим: expanding window

1. Задаем минимальный размер обучения `min_train = 252` торговых дня после появления первых режимов.
2. Для каждого дня `t`, начиная с `min_train`:
   - берем только историю до `t` включительно;
   - строим или обновляем матрицу переходов;
   - считаем вероятности режима на `t+1`;
   - считаем `mm_signal_t`;
   - открываем позицию на `open_{t+1}`;
   - закрываем позицию на `close_{t+1}`;
   - записываем результат.

### Альтернативный режим: rolling window

В rolling-варианте матрица строится не по всей прошлой истории, а по последним `N` дням. Это может лучше адаптироваться к смене структуры рынка, но повышает шум.

Кандидаты для будущего теста:

```text
N = 252
N = 504
N = 756
```

### Запреты против lookahead

- Нельзя строить матрицу на всей истории и применять ее к прошлым датам.
- Нельзя использовать `close_{t+1}` при расчете сигнала для сделки на день `t+1`.
- Нельзя оптимизировать параметры на тестовом окне.
- Нельзя включать текущий переход `t -> t+1` в матрицу, если по нему уже оценивается сделка.

## Доходность и издержки

Доходность следующего дня:

```text
oc_return_next_t = close_{t+1} / open_{t+1} - 1
```

Доходность стратегии:

```text
strategy_return_t =
    position_t * oc_return_next_t
    - commission
    - slippage
```

Комиссии и проскальзывание должны быть параметрами бэктеста. Если данных о комиссии пока нет, первый отчет можно сделать в двух вариантах: gross и net с условной издержкой.

## HMM как следующий слой

HMM не заменяет базовую MM-модель на первом этапе. Его лучше добавить после baseline, чтобы понять, дает ли скрытая модель дополнительную пользу.

Минимальные признаки для HMM:

```text
cc_return_t
abs(cc_return_t)
high_low_range_t = high_t / low_t - 1
open_close_return_t = close_t / open_t - 1
```

Правила HMM walk-forward:

1. На каждом train-окне fit выполняется только на прошлом.
2. Скрытые состояния сортируются по средней доходности в train-окне:
   - минимальная средняя доходность -> `Bear`;
   - средняя -> `Sideways`;
   - максимальная -> `Bull`.
3. Вероятности следующего режима берутся из transition matrix HMM для текущего скрытого состояния.
4. HMM-сигнал считается тем же способом: `P(Bull next) - P(Bear next)`.
